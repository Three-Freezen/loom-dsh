# Loom for DSH v0.1.1

> 修复版本：解决 0.1.0-beta 中**设置窗口打不开**的问题。建议所有 0.1.0-beta 用户升级（安装版可直接在应用内更新）。

## 修复内容

### 1. 设置窗口打不开（主要修复）

- **症状**：托盘右键 →「设置」或 `loom-dsh ui settings` 没有任何反应；进程还在、日志也没有新记录；`loom-dsh ui render` 只渲染出第一张图就停住不退出。
- **根因**：0.1.0-beta 新增的「应用更新」卡片里 `ProgressBar.Value="{Binding UpdateProgress}"` 用了默认的 **TwoWay** 绑定，而该属性只有 `private set`。WPF 在创建设置页时抛出
  `InvalidOperationException: A TwoWay or OneWayToSource binding cannot work on the read-only property 'UpdateProgress'`，
  该异常在窗口 `Show()` 之前就被 dispatcher 未处理异常处理器吞掉 → 窗口静默不出现。
- **修复**：只读展示属性显式 `Mode=OneWay`。

### 2. 界面失败不再“静默”

- 设置 / 首次运行向导 / 报告窗口创建失败时：写日志 + 弹出一次可读的错误提示（此前完全无反馈）。
- `ui render` 在 `finally` 里无条件退出（渲染失败也会返回非 0 并留下日志），不会再“假死”在托盘里。

### 3. 日志不再被自己覆盖

- `AppServices.TryLogException` 改为复用服务自身的 logger。此前它会另开一个 `FileLogger` 追加同一文件，两个句柄各自维护偏移互相覆盖，导致真正的 ERROR 行被后续 INFO 截断 —— 本次排障时正是这行关键报错被截成了半行。

### 4. 预览回归增强

- `ui render` 新增 `settings-update-{dark,light}.png`（渲染「更新与兼容」页，即应用更新卡片所在页），共 **10 张** PNG；
  这类“编译期看不出、运行期才炸”的绑定问题从此纳入回归。

## 安装与升级

### 安装版（推荐，支持应用内更新）

- 已装 0.1.0-beta：托盘右键 →「检查应用更新」→ 设置 →「更新与兼容」→「下载更新」→「重启并更新」（静默安装并自动重启）。
- 或直接下载 `loom-dsh-Setup.exe` 覆盖安装：免管理员，升级与卸载都不会删除 `<安装目录>\Data` 用户数据。

### 绿色版

- 下载 `loom-dsh.exe` 覆盖即可；数据目录仍为 `%LOCALAPPDATA%\Loom`（便携模式为 `<exe目录>\Data`）。

```powershell
loom-dsh.exe version          # 确认升到 0.1.1
loom-dsh.exe ui render --data-root .\preview   # 期望退出码 0 + 10 张 PNG
```

## 系统要求与说明

- Windows 10 x64 或更高；自包含 .NET 10 单文件，**无需预装运行时**；免管理员安装到用户目录。
- **未签名**：SmartScreen 可能提示，请核对上方 SHA256；代码签名在后续版本。
- 应用内更新：只有 Inno 安装版支持“下载 + 静默升级 + 自动重启”；绿色版/开发版可检查版本但需手动下载安装包。
- 已知限制沿用 0.1.0-beta：真机 smoke 项（正式安装包安装/升级/卸载、通知区右键与状态面板、静默升级自动重启、数据目录 ACL）、
  自动迁移只复制不删除、迁移时仅重写 5 类绝对路径。
