# Loom for DSH v0.2.0

> 状态：**本地版本，尚未发布**。本文档为发布做准备；产物大小与 SHA256 均**待发布时生成并填充**（见文末占位）。
> 本地全量单测 **403/403 PASS**，`ui render` 产出 **12 张**预览。
> 建议所有 0.1.1 用户升级：修复了跨进程互斥失效等 P1 问题，并带来策略 A 自动升级、包级恢复与离线完整回滚（自动升级与包级恢复默认关闭、标实验性）。

## 修复内容

### 1. 跨进程操作门实际失效（P1）

- **症状**：托盘与 CLI 的写操作本应互斥，实际上互斥只在“等待成功到方法返回”的几微秒内有效，两个进程可同时改 profile。
- **根因**：`AcquireAsync` 里用 `using var mutex`，方法返回时互斥量已被 `Dispose`；`Releaser` 再调 `ReleaseMutex()` 只会抛 `ObjectDisposedException` 并被吞掉。另外 Windows Mutex 是**线程亲和**的，`await` 之后换线程释放会抛 `ApplicationException`（同样被吞），等于没修。
- **修复**：互斥量的 `WaitOne/ReleaseMutex/Dispose` 全部交给一条专属所有者线程；`Releaser.Dispose` 通知它释放完成后再返回，跨进程互斥覆盖整个操作生命周期。新增 `TryAcquireCrossProcessLease` 供 CLI 长操作预占。

### 2. 长操作与托盘的并发窗口（P1）

- **症状**：`upgrade` / `recovery` 这类长操作不入队（单包安装默认 15 分钟、包级恢复默认 10 分钟，远超队列语义），直连时可能和托盘正在执行的写操作同时改 profile。
- **修复**：直连前先 `WaitOne(0)` 非阻塞探测跨进程门——拿不到返回退出码 **4**（忙），拿到则一直持有到命令结束；`--dry-run` 与只读的 `recovery plan` 不受影响。

### 3. 日志跨进程互相覆盖（P2）

- 托盘与 CLI 各自长期持有 `logs\loom.log` 句柄会记住打开时的偏移，后写者从陈旧偏移覆盖前者行首。
- 现在每次写入都在按数据根派生的命名互斥量 `Local\LoomForDsh-<sha256(数据根)前16位>-Log-v1` 下重新打开文件（打开即定位 EOF）并立即关闭；等锁最多 5 秒，超时仍写入（宁可不丢日志）。
- 仍为 `Local\`（会话内）：跨会话只靠“打开即定位 EOF”兜底，极端交错下仍可能互相覆盖；且等锁上限 5 秒会阻塞调用线程。

### 4. 其他健壮性修复（P2）

- **config/state 升级前备份**：旧 schema 或字段需要归一化时先复制为 `config.json.bak-<yyyyMMdd-HHmmss>` / `state.json.bak-<yyyyMMdd-HHmmss>`，损坏文件同样先留 `.bak` 再隔离。
- **后台字段不再覆盖用户设置**：更新检查时间戳等后台写回改走锁内 `MutateConfig`（只改该字段）；设置页整份保存前会合并磁盘上更新的后台字段。
- **Tick 看门狗与安全复位**：重叠 Tick 直接跳过；单轮超过 5 分钟则取消该轮、等旧 Tick 退出（最多 5 秒），仍未退出就记为 abandoned 并写 ERROR、发 `Failed` 通知，下一轮继续（不再永久停摆）；`doctor` 新增 `tick` 检查项。
- **非交互会话不弹模态框**：服务化启动 / 断开会话 / session 0 只写日志，避免 MessageBox 永久阻塞 UI 线程；UI 线程异常每次记 ERROR，连续 3 次才提示一次。
- **通知去重**：从“只记最后一个 eventId”改为 `state.json` 的 `recentNotifiedEventIds`（最近 20 个，FIFO），A/B/A 与进程重启都不会重复通知。
- **托盘数据根握手**：托盘启动写 `tray-root.json`（pid/root/版本），CLI 据此识别托盘真实数据根；托盘在另一数据根且未显式 `--data-root` 时，写命令直接拒绝（退出码 2）；只读的 `--dry-run` / `recovery plan` 不受这条拒绝影响。
- **应用内更新校验和**：下载后读取 `SHA256SUMS.txt` 校验安装包；清单缺失/无条目时明确标记“未校验”但仍可继续，哈希不一致则删除安装包并报错；执行前另按第 6 条用下载旁车复验（含退出托盘后的跨进程 `--apply`）。
- **CLI 参数错误退出码**：从 4（忙）改为 1（失败），直接 CLI 与托盘队列执行器一致。
- **`ui render` 失败返回非 0**：启动期初始界面失败会记录退出码并由 render 模式带出，不再“假死”或被吞成 0。

### 5. 跨进程互斥只覆盖同一登录会话（P2）

- 写操作门与日志锁的名字改为由数据根派生：`Local\LoomForDsh-<sha256(数据根)前16位>-Operation-v1` / `-Log-v1`。不同数据根不再互相阻塞（旧名不含数据根，A profile 的 15 分钟安装会让 B profile 的 `upgrade` 直接 Busy）。
- 数据根下新增 `loom.operation.lock`（`FileShare.None`）文件锁，补齐跨登录会话互斥：便携版共享目录被两个用户使用、或 session 0 计划任务与交互托盘共享同一数据根时，写操作仍严格串行。
- 保留 `Local\` 前缀：普通用户没有 `SeCreateGlobalPrivilege`，`Global\` 会创建失败。`SingleInstance` 与安装器 `AppMutex` **有意**保持 `Local\LoomForDsh-Instance-v1`（人机单实例语义，安装器靠同名 mutex 判断托盘是否在运行）。

### 6. 应用内更新：执行前复验安装包（P2）

- 旧实现只在“下载后立即执行”的同一进程内复验哈希；退出托盘后运行 `loom-dsh update --apply`（新进程）会跳过校验，也不校验版本。
- 现在下载成功写旁车 `<数据根>\updates\loom-dsh-Setup.exe.meta.json`（sha256 / version / size / downloadedAt / 绝对路径）；每次 apply 前按 文件存在 → 旁车 → SHA256/大小 → 安装包内嵌 `ProductVersion` → 目标版本高于当前 逐项校验，任一不符即拒绝并提示重新下载。
- 旁车不能代替 `SHA256SUMS.txt`：清单可用时两者都校验；清单取不到时仍会写旁车，因此“未校验”的下载仍可 apply，但它只证明文件未被替换/改动，不能证明构建者可信。
- 升级后清理标记改写绝对路径（旧相对值按数据根解析），避免从计划任务/托盘启动时删错或删不到；下载目录解析结果缓存，getter 不再反复探测 Downloads。

## 新增内容

### 1. 策略 A 自动升级（默认关闭，实验性）

- 设置页「更新与兼容 → 插件自动升级（策略 A）」：总开关（默认关）、允许 major 升级（默认关）、允许预发布版本（默认关）。
- 自动升级只在**开关打开 + 策略 A + DSH 完全退出 + profile 未被占用**时由 Tick 执行；每次最多处理 3 个“不兼容且版本已知”的插件。
- 决策是纯函数：候选必须在新运行时上 evaluator=compatible、非 deprecated、平台含 win32、静态预检通过；稳定版优先，major/prerelease 需显式允许。**没有兼容版本时只提示人工，绝不自动授予风险豁免。**
- 执行：写前备份 profile 核心文件到 `restore-backup\<opId>\` → `dsh plugin --profile desktop add <pkg>@<ver> --save-exact` → 回读版本/精确 spec/bundles/lockfile → 失败只按本次备份回滚；审计写 `reports\upgrade-<opId>.json`。
- CLI：`loom-dsh upgrade [--pkg <name>] [--dry-run] [--json] [--allow-prerelease]`；不带 `--pkg` 时按最近一次检查结果批量处理。

### 2. 包级恢复（默认关闭，实验性）

- 设置页「更新与兼容 → 包级恢复（实验性）」：启用开关（默认关）、允许联网回退（默认关，当前仅预留）、「回滚上一次包级操作」按钮。
- CLI：`loom-dsh recovery plan`（只出计划，不写文件）/ `recovery apply [--snapshot <id>] [--dry-run]`。
- 流程：备份 `package.json`/`pnpm-lock.yaml` → 按快照写回（保留用户新增顶层字段）→ `dsh plugin --profile desktop install --offline --frozen-lockfile` → 校验；失败只回滚当前 op。
- 前置：**DSH 必须完全退出**（Loom 不会结束进程）；`packageRestoreEnabled=false` 时直接拒绝且不写 profile。

### 3. 离线完整回滚

- `loom-dsh recovery rollback <opId>`（`--dry-run` 只校验回滚点）：读 `restore-backup\<opId>\package-restore.json`，恢复文件 → 离线重装 → 再次校验；只影响该 op，不联网、不使用 `file:<tgz>`（归档 tarball 最后手段未实现，保留设计）。
- 回滚点保留份数由 `keepRollbackBackups` 控制（默认 5），清理只删最旧的、绝不删当前 op。

### 4. CLI 与设置页

- 新命令：`upgrade`、`recovery plan|apply|rollback`；退出码沿用 0 成功 / 1 失败 / 2 待人工 / 3 不可用 / 4 忙。
- 设置页新增上述两组卡片与回滚按钮；`ui render` 为 **12 张**预览（含 `settings-update-{dark,light}.png` 与整页 `settings-compat-{dark,light}.png`，后者覆盖策略 A/包级恢复卡片），且 render 模式跳过安装包清理与自动检查更新、不启动队列与定时器。

## 安装与升级

### 安装版（推荐，支持应用内更新）

- 已装 0.1.1：托盘右键 →「检查应用更新」→ 设置 →「更新与兼容」→「下载更新」→「重启并更新」（静默安装并自动重启）。
- 或发布后从 Release 下载 `loom-dsh-Setup.exe` 覆盖安装：免管理员，升级与卸载都不会删除 `<安装目录>\Data` 用户数据。

### 绿色版

- 发布后下载 `loom-dsh.exe` 覆盖即可；数据目录仍为 `%LOCALAPPDATA%\Loom`（便携模式为 `<exe目录>\Data`）。

```powershell
loom-dsh.exe version          # 确认升到 0.2.0
loom-dsh.exe upgrade --dry-run --pkg <包名>   # 只出决策与命令，不写任何文件
loom-dsh.exe recovery plan --json            # 包级恢复计划（开关未开时会给出原因）
```

## 已知限制

- **策略 A 自动升级与包级恢复默认关闭、标实验性**：需在设置里显式打开；自动升级还要求 DSH 完全退出且 profile 未被插件管理器占用。
- **包级恢复要求 DSH 完全退出**（含托盘/后台进程）；App 在跑时直接失败并给人工入口。
- **自动升级失败只回滚 profile 文件**，不额外修复 `node_modules`（可用 `recovery apply` 或人工 `install --offline --frozen-lockfile`）。
- **包级恢复当前只走离线**：`install --offline --frozen-lockfile`；设置里的「允许联网回退」是预留开关，当前没有执行路径会真正发起联网安装。
- **跨进程 `config.json` 写竞态**仍未协调：托盘与 CLI 各自原子写，极端并发下后写者覆盖先写者（快照/回滚点/state 不受影响）。
- **日志锁仍为 `Local\`**（同一登录会话）：跨会话只靠“打开即定位 EOF”兜底，且等锁上限 5 秒会阻塞调用线程。
- **未签名**：安装包与 exe 均未做代码签名，SmartScreen 可能提示；请核对文末 SHA256（发布后）。
- **真机 smoke 待做**：正式安装包安装/升级/卸载、通知区右键与前台锁、静默升级自动重启、数据目录 ACL，以及二期新功能的真机路径。
- 应用内更新需要能访问 GitHub；清单 `SHA256SUMS.txt` 取不到时会标记“未校验”但仍允许继续（离线/网关场景）。

## 系统要求与说明

- Windows 10 x64 或更高；自包含 .NET 10 单文件，**无需预装运行时**；免管理员安装到用户目录。
- 应用内更新只有 Inno 安装版支持“下载 + 静默升级 + 自动重启”；绿色版/开发版可检查版本但需手动下载安装包。
- 数据目录：安装版 `<安装目录>\Data`；绿色版/开发版 `%LOCALAPPDATA%\Loom`；便携模式 `<exe目录>\Data`。
