## 1. 安装包（Inno Setup 6）

### 1.1 编译与产物

```powershell
# 正式安装包（版本号通过 /DAppVersion 注入，默认 0.1.0）
& "C:\Users\<用户>\AppData\Local\Programs\Inno Setup 6\ISCC.exe" `
    /DAppVersion=0.1.0 "installer\loom-dsh.iss"
# 一条龙（默认行为 = 发布 exe + 安装包 + SHA256SUMS + 发布说明；找不到 ISCC 只警告不失败）
powershell -ExecutionPolicy Bypass -File scripts\publish.ps1
# 只发布绿色版 exe（不生成安装包）
powershell -ExecutionPolicy Bypass -File scripts\publish.ps1 -NoInstaller
# 只重打安装包（复用已有 dist\loom-dsh.exe）
powershell -ExecutionPolicy Bypass -File scripts\pack-installer.ps1 -SkipPublish
```

- `scripts\publish.ps1` 不带参数时**默认生成安装包**（在找到 ISCC 时）；`-NoInstaller` 只出绿色版；
  `-Installer` 保留为兼容别名。
- `pack-installer.ps1` 通过 `/DMyExePath=<绝对路径>` 把实际发布的 exe 传给 iss（支持自定义 `-OutputDir`，
  不会误打包旧 dist exe）；版本号来自 `Loom.csproj <Version>`，可用 `-Version` 覆盖。

产物固定为 `dist\loom-dsh-Setup.exe`（**文件名不带版本号**），配合
`.../releases/latest/download/loom-dsh-Setup.exe` 直链永远拿到最新版，也为未来应用内更新留好接口。

### 1.2 关键 [Setup] 配置

| 配置 | 值 | 说明 |
|---|---|---|
| `AppId` | `{1172EF08-41CF-4CC6-9EDD-4B3E51C20E14}` | 固定 GUID，升级识别 + 卸载注册表键；永不修改 |
| `AppName` / `AppVersion` | Loom for DSH / `/DAppVersion`（默认 0.1.0） | 版本与 `Loom.csproj <Version>` 同源 |
| `PrivilegesRequired` | `lowest` | 免管理员，装到用户目录（与 DeskOrder 相同方式） |
| `DefaultDirName` | `{userpf}\Loom` = `%LOCALAPPDATA%\Programs\Loom` | 向导里可改；不写 Program Files |
| `OutputBaseFilename` | `loom-dsh-Setup` | 固定名，in-app update 直链依赖 |
| `Compression` | `lzma2/max` + `SolidCompression` | 约 173 MB exe → 约 52 MB 安装包 |
| `ArchitecturesAllowed` | `x64compatible` | 主程序 win-x64 self-contained |
| `CloseApplications` / `AppMutex` | `yes` / `Local\LoomForDsh-Instance-v1` | 升级时等待/关闭旧托盘实例（见 §5.3 实测） |
| `SetupIconFile` / `UninstallDisplayIcon` | `src\Loom\Assets\Icons\loom-check-light.ico` / `{app}\loom-dsh.exe` | 安装程序与主程序同图标 |

### 1.3 安装布局

```
%LOCALAPPDATA%\Programs\Loom\          ← {app}（PrivilegesRequired=lowest，默认路径）
├─ loom-dsh.exe                        ← 单文件 self-contained 主程序（唯一 [Files] 项）
├─ unins000.exe / unins000.dat         ← Inno 卸载器与卸载日志
└─ Data\                               ← 用户数据根（[Dirs] 创建，uninsneveruninstall）
   ├─ config.json / state.json
   ├─ migration.json                   ← 首次从 %LOCALAPPDATA%\Loom 迁移的标记（§3）
   ├─ snapshots\ restore-backup\ reports\ logs\ journal\ queue\ helper\
   └─ loom.operation.lock
```

`Data\` **不在 [Files] 清单内**，卸载器只删除自己写入的文件 → 升级/卸载都不会删除用户数据。

### 1.4 交互安装 / 静默安装

- 交互：向导可选安装路径；可选“创建桌面快捷方式”任务；结束页可勾选立即启动。
- 静默：`loom-dsh-Setup.exe /VERYSILENT /NORESTART /DIR=D:\path`；
  升级场景（同 AppId 已安装）`InitializeSetup` 会先静默卸载旧版再装新版，避免“已存在该软件”弹窗卡住 `/SILENT` 流程。
- 静默升级完成后，`[Run]` 的 `runasoriginaluser` 项会自动重启应用（首次静默安装不拉起托盘）。
- 交互升级时若检测到旧安装位置，会把目录页预填为原路径。

### 1.5 沙箱测试变体（仅用于受限环境端到端验证）

DSH 沙箱只允许写工作区：实测**拒绝 HKCU 注册表写入与 `%APPDATA%` 写入**。正式安装包在这种环境会以
退出码 4 失败（写卸载注册表项/开始菜单图标被拒）。因此 `loom-dsh.iss` 提供编译期开关：

```powershell
# 用脚本一键生成沙箱测试安装包（输出 .tmp-installer\loom-dsh-Setup-test.exe，不进发布物）
powershell -ExecutionPolicy Bypass -File scripts\pack-installer.ps1 -SkipPublish -SandboxTest
# 等价的手工命令
ISCC.exe /DAppVersion=0.1.0 /DTestSandbox=1 `
    /DMyOutputDir=..\.tmp-installer /DMyOutputBaseFilename=loom-dsh-Setup-test `
    installer\loom-dsh.iss
```

- `TestSandbox` → `CreateUninstallRegKey=no`（`unins000.exe` 仍会生成，可手动运行），图标改落 `{app}\sandbox-icons`。
- 正式产物**不带**该定义；两种产物除注册表项/图标位置外安装行为一致。
- 同一限制导致沙箱内卸载后 `unins000.exe` 可能残留（卸载器自删依赖 RunOnce 注册表）；真实系统正常删除。

## 2. 数据目录

### 2.1 解析优先级（`DataRootResolver.Resolve`）

| 顺序 | 条件 | 数据根 | `DataRootSource` |
|---|---|---|---|
| 1 | `--data-root <dir>` / `LoomOptions.DataRoot` | 指定目录 | `Explicit` |
| 2 | `<exe目录>\Data\portable.flag` 存在 | `<exe目录>\Data` | `Portable` |
| 3 | `<exe目录>\unins000.exe` 存在（Inno 安装版） | `<安装目录>\Data` | `Installed` |
| 4 | 其余（`dotnet run` / `bin\Debug` / 解压绿色版） | `%LOCALAPPDATA%\Loom` | `LegacyDefault` |

- **`--data-root` 行为与旧版本完全一致**（最高优先级，不自动迁移）；CLI 各命令与托盘进程共用同一套解析
  （`LoomServiceFactory` 解析；`Program` 的托盘命令队列路径也调用同一 resolver，否则安装版 CLI 找不到托盘队列）。
- 开发目录没有 `unins000.exe`，因此 `dotnet run`、测试、现有验收脚本仍是 `%LOCALAPPDATA%\Loom`，行为不变。
- 便携模式：把 `portable.flag`（内容任意）放进 `<exe目录>\Data\`，解压后的绿色版即可把数据放在 exe 旁边。
- 测试钩子 `LOOM_LEGACY_DATA_ROOT`（**仅测试/验收用**）：覆盖“旧默认根”，生产环境不要设置；
  代码中已注明 test-only。

### 2.2 数据根内容（`LoomPaths`）

| 路径 | 内容 |
|---|---|
| `config.json` | 用户设置（安装目录覆盖、策略、保留数、主题、日志级别等） |
| `state.json` | 快照指针、更新阶段、上次操作/检查摘要（含**绝对路径**，迁移时会重写） |
| `snapshots\<id>\` | 快照归档 + `snapshot.json` |
| `restore-backup\<op>\` | 文件级还原前的备份 |
| `reports\` | check / restore 的 Markdown+JSON 报告 |
| `journal\` | 操作日志（崩溃恢复用） |
| `logs\loom.log` | 运行日志（5 MB × 3 轮转） |
| `queue\requests|results\` | 托盘与 CLI 的进程间命令队列（**不迁移**，见 §3.2） |
| `helper\helper.mjs` | 从 exe 内嵌资源解压的 Electron helper |
| `loom.operation.lock` | 跨进程操作互斥（**不迁移**） |
| `migration.json` | 迁移标记（仅安装版首启迁移后存在） |

数据根与 DSH_HOME / profile **完全分离**，Loom 不会把工具数据写进 `~\.dsh` 或 DSH 安装目录。

### 2.3 `version --json` 可见性

```json
{
  "tool": "loom-dsh",
  "version": "0.1.0",
  "dataRoot": "D:\\BS\\...\\app\\Data",
  "dataRootSource": "Installed",
  "installedBuild": true,
  "legacyDataRoot": "C:\\Users\\<user>\\AppData\\Local\\Loom",
  "dsh": { "...": "..." }
}
```

`dataRootSource` ∈ `Explicit|Portable|Installed|LegacyDefault`，用于安装/迁移排障与验收取证。

## 3. 旧数据迁移（C 盘 `%LOCALAPPDATA%\Loom` → 安装目录 `Data`）

### 3.1 自动迁移（安装版首启）

`LoomServiceFactory.Create` 在**读取 config/state 之前**执行：

1. 解析数据根；仅当 `DataRootSource` 为 `Installed`/`Portable` **且**生效根 = `<exe>\Data` **且**该根
   尚不存在 `config.json` **且** 旧默认根存在时触发；
2. 复制旧根全部文件到新根（**只复制不删除**，幂等，不覆盖已存在文件）；
3. 重写复制过来的 `config.json` / `state.json` 中旧根前缀的绝对路径（见 §3.2）；
4. 写 `<DataRoot>\migration.json` 标记；
5. 任何失败只写日志警告，**不阻塞启动**。

`migration.json` 示例：

```json
{
  "schemaVersion": 1,
  "migratedAt": "2026-11-14T13:45:00+08:00",
  "sourceRoot": "C:\\Users\\<user>\\AppData\\Local\\Loom",
  "targetRoot": "D:\\Apps\\Loom\\Data",
  "filesCopied": 42,
  "filesSkipped": 6,
  "pathsRewritten": 5,
  "removeSource": false,
  "errors": 0,
  "toolVersion": "0.1.0"
}
```

### 3.2 跳过规则与路径重写

- 跳过：`queue\` 整棵子树（一次性 IPC）、`*.lock`（含 `loom.operation.lock`）、`*.tmp`、`*.tmp-*`
  （原子写临时文件）、`*.corrupt-*`（已隔离的坏文件）、`*.part`、根目录旧 `migration.json`。
- 重写（仅当值位于旧根之下，大小写不敏感，保留其余字段）：
  - `state.json`：`lastSnapshot.path`、`preUpdateSnapshot.path`、`lastOperation.reportPath`、`lastCheck.reportPath`
  - `config.json`：`dataRoot`

### 3.3 CLI `migrate-data`

```powershell
loom-dsh migrate-data                 # 迁移旧默认根 → 当前数据根（已初始化则跳过）
loom-dsh migrate-data --dry-run       # 只统计将复制多少文件，不写任何东西
loom-dsh migrate-data --remove-source # 迁移成功后删除旧目录（有安全校验，见下）
loom-dsh migrate-data --json          # 机器可读
loom-dsh migrate-data --data-root D:\path\Data   # 指定目标数据根
```

- 目标根已有 `config.json` → 返回 `skippedReason=target-initialized`（退出码 0），不重复迁移。
- 源目录不存在 → `skippedReason=source-missing`（退出码 0）。
- 源=目标 → `same-root`（退出码 3 不可用）；其他失败 → 退出码 1。
- `--remove-source` 安全规则：仅当本次确有复制、或目标 `migration.json` 证明旧根曾迁移到该目标，
  且源不是磁盘根目录、目标不在源目录内时才删除；否则只警告不删除。

> 自动迁移只复制不删除。确认新目录工作正常后，可手动执行 `loom-dsh migrate-data --remove-source`
> 清理 C 盘旧目录；也可以先保留一段时间再手动删除。

## 4. 升级 / 卸载

### 4.1 升级

两种方式等价（同 AppId 覆盖安装，`InitializeSetup` 先静默卸载旧版）：

```powershell
# 手动升级（交互）
dist\loom-dsh-Setup.exe
# 静默升级到原安装目录（应用内更新使用同样的参数）
dist\loom-dsh-Setup.exe /SILENT /DIR="D:\Apps\Loom"
```

- 升级只替换 `loom-dsh.exe` / 卸载器文件；`Data\` 不在 [Files] 清单 → **数据保留**（首启不会重复迁移，
  因为 `config.json` 已存在）。
- `scripts\publish.ps1 -Installer` 每次产出的安装包文件名固定，可直接覆盖发布。

### 4.2 卸载

- “设置 → 应用 → Loom for DSH → 卸载”，或运行 `<安装目录>\unins000.exe`（可加 `/VERYSILENT /NORESTART`）。
- 卸载删除主程序、快捷方式、开始菜单项；**`Data\` 目录保留**（含快照/报告/设置/迁移标记）。
- 彻底清理：卸载后手动删除 `<安装目录>\Data` 与（如仍有）`%LOCALAPPDATA%\Loom`。

## 5. 应用内更新（已实现：GitHub Releases）

安装版（exe 旁有 `unins000.exe`）在「设置 → 更新与兼容 → 应用更新」提供检查、下载与一键静默升级；
启动后台检查默认开启（24 小时最多一次，可在设置里关闭）。绿色版/开发版仍可检查版本，但不会应用内安装，
会引导到 GitHub Releases 手动下载。

### 5.1 仓库与发布约定

- 公开仓库：`https://github.com/Three-Freezen/loom-dsh`（MIT 许可）。
- 版本探测：`https://github.com/Three-Freezen/loom-dsh/releases/latest` 的 302 `Location` 中 tag
  （REST API 仅兜底，避开匿名 60 次/小时配额）。
- 固定资产名：`loom-dsh-Setup.exe`，直链
  `https://github.com/Three-Freezen/loom-dsh/releases/latest/download/loom-dsh-Setup.exe`。
- 版本比较：`SemVersion`（支持预发布标识）；远端 tag 不高于当前 `LoomPaths.ToolVersion` 时视为最新。
- 发布新版本：改 `Loom.csproj <Version>` → `scripts\publish.ps1` → 打 tag `v<版本>` → 在 GitHub Release
  上传 `dist\loom-dsh-Setup.exe`（资产名保持不变）。

### 5.2 行为与 CLI

1. **检查**：`CheckAsync()` 解析最新 tag；成功/失败都会写 `config.json.lastUpdateCheckUtc` 做 24h 节流。
2. **下载**：下载到用户“下载”文件夹（不可写时回退 `<数据根>\updates`），`.part` 原子改名；< 1 MB 视为失败。
3. **应用**：`/SILENT /DIR="<当前安装目录>"` 启动安装包 → 本进程退出释放 mutex → Inno 升级 → `[Run]` 重启。
4. **升级后清理**：`<数据根>\pending-setup-cleanup.txt` 记录安装包；新版首启版本更高时删除（默认开启，可关）。
5. **失败处理**：网络/代理/限流错误转为中文提示，不影响插件守护。

```powershell
loom-dsh update                    # 只检查
loom-dsh update --json             # 机器可读
loom-dsh update --download         # 检查 + 下载
loom-dsh update --apply            # 已下载时静默升级（托盘运行中返回退出码 4）
loom-dsh update --download --download-dir D:\tmp   # 覆盖下载位置（测试）
```

离线自测（在仓库根目录执行）：`--update-source <目录>` 把目录里的固定资产当本地更新源（不联网），配合
`--download-dir` 可完整验证“检查 → 下载 → Ready”。QA 已用该钩子做闭环。

### 5.3 实现事实（DeskOrder 同款模式）

核心事实由 `AppInstallInfo` 提供：

```csharp
AppInstallInfo.IsInstalledBuild            // exe 旁边有 unins000.exe（开发目录为 false）
AppInstallInfo.InstallDir                  // 安装目录（未安装为 null）
AppInstallInfo.SetupAssetName              // 固定资产名 "loom-dsh-Setup.exe"
AppInstallInfo.BuildSilentUpgradeArguments(dir)  // /SILENT /DIR="<当前安装目录>"
AppInstallInfo.DefaultInstallDir           // %LOCALAPPDATA%\Programs\Loom
```

实现细节：

1. **检查**：请求 GitHub `releases/latest`（网页端点 302 → tag，避开 REST API 匿名限流），
   用 `SemVersion` 与当前版本比较；
2. **下载**：`releases/latest/download/loom-dsh-Setup.exe`（固定文件名）下载到用户“下载”文件夹，
   先写 `.part` 再原子改名；可对照 `SHA256SUMS.txt` 校验；
3. **应用**：**先退出托盘/释放 `Local\LoomForDsh-Instance-v1` 单实例锁**，再
   `Process.Start(Setup, "/SILENT /DIR=\"<安装目录>\"")`，安装器 `[Run]` 项装完自动重启应用；
4. **前提（实测结论见 §5.3）**：若旧实例仍持有 mutex，/SILENT 安装会被 AppMutex 拦下（退出码 1），
   所以 updater 必须先退出应用再启动安装器；
5. 安装包与 `loom-dsh.exe` 均未签名：将来配合代码签名 + SHA256 校验再启用自动更新。

### 5.4 AppMutex 与 `Local\` 前缀实测（2026-11-14）

- 探针安装包（`CheckForMutexes`）：未持 mutex → `Local\LoomForDsh-Instance-v1`=0、无前缀=0；
  持有该 mutex → 两者均=1。**Inno Setup 支持 `Local\` 前缀**（同会话默认命名空间即 Local）。
- 真实安装包 + 持 mutex 运行 `/VERYSILENT /SUPPRESSMSGBOXES`：setup 识别“Loom for DSH 当前正在运行”
  并中止（退出码 1，0.5 s），不会永久挂起；交互安装会提示用户关闭应用。
- 结论：`AppMutex=Local\LoomForDsh-Instance-v1` 保留；`CloseApplications=yes` 补充覆盖文件占用。

## 7. 已知限制 / 风险

1. **未签名**：安装包与 exe 都未做代码签名，SmartScreen 可能提示；正式分发前建议签名。
2. **沙箱验证差异**：DSH 沙箱禁止 HKCU 注册表与 `%APPDATA%` 写入，正式安装包的“注册卸载项/开始菜单图标”
   无法在沙箱内完整验证（用 §1.5 测试变体验证安装/升级/卸载机制）；真机需一次人工安装确认。
3. **自动迁移只复制不删除**：C 盘 `%LOCALAPPDATA%\Loom` 会保留，需要用户手动执行
   `migrate-data --remove-source` 或删除；文档已说明。
4. **并发写入**：迁移发生在启动最早阶段且不覆盖已有文件，但仍建议升级/首次启动时关闭托盘实例
   （安装器 `CloseApplications`+`AppMutex` 会处理）。
5. **便携标记**：`portable.flag` 仅作为显式覆盖；安装版无需该文件（`unins000.exe` 自动识别）。
6. **真实用户数据不可写**：受限环境（本沙箱）中旧默认根只读时自动迁移仍可复制（读权限足够），
   但迁移后写入新根由安装目录权限决定。
