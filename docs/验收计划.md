# Loom for DSH · 验收计划（范围 A）

> 依据：`实现方案-v2.md` §16.3（A01–A30）、§16.4 上线门槛；`方案审核报告.md` 第三节。
> 设备：Windows 10/11 x64；真实环境 **只读**，所有写操作用沙箱副本。
> 状态图例：✅ 已覆盖（自动化）｜🟡 手工/半自动｜⬜ 待 QA

## 一、测试环境

| 环境 | 内容 |
|---|---|
| 真实环境（只读） | `D:\DeepSeek`、`C:\Users\<user>\.dsh\profiles\desktop`、更新器缓存 |
| 沙箱 | `%TEMP%\loom-accept\<guid>\`：假安装目录（`resources\runtime\primary-runtime\runtime.json`、`resources\runtime\cli\bin\dsh.cmd`、空 `resources\app.asar`）+ 假 DSH_HOME（真实 profile 副本，或 3 插件最小副本）+ 工具数据目录 |
| 命令注入 | `--install-dir` / `--dsh-home` / `--profile-dir` / `--data-root` 全部显式传入，绝不落到真实 profile |
| 破坏性演练 | A12（装到一半崩溃）、A14（恢复后还原）只在沙箱副本执行 |

> 注意：在本会话的 DSH 沙箱里 `%LOCALAPPDATA%` 不可写，运行 CLI/托盘时统一加
> `--data-root <工作区内目录>`；真实用户环境不需要。

## 二、A01–A30 验收矩阵

| ID | 场景 | 期望 | 验证方式 | 覆盖 |
|---|---|---|---|---|
| A01 | 基线快照 | snapshot.json + 配置文件齐全；不写安装目录；报告可读 | 沙箱 `loom-dsh snapshot --json --install-dir ... --dsh-home ... --data-root ...`；断言 snapshots 目录、profile 副本、report.json/md、安装目录哈希未变 | 自动化 xunit + 脚本 |
| A02 | 插件变化后自动快照 | debounce 后生成新快照；不重复；旧快照保留 | 修改沙箱 profile package.json → 等待 Tick（或 CLI 触发）→ 快照数量+1 | 半自动 |
| A03 | 下载开始（temp-*）即快照 | 最终 installer 出现前完成；记录目标版本 | 沙箱伪造 `pending\temp-<ver>-...exe` → 运行 Tick → 冻结 pre-update 快照 + PendingUpdate 记录 | 自动化（UpdaterMonitor+Snapshot） |
| A04 | 旧 pending 不误触发 | 0.2.2-rc.1 残留包被忽略；不重复快照 | 真实更新器缓存只读测试（stale ≤ 当前版本） | 自动化 |
| A05 | appVersion/dshVersion 分离 | 仅 app 变化不触发还原/检查；仅 dsh 变化触发 check | 沙箱改 runtime.json desktopVersion、模拟 dshVersion 变化 | 自动化（LoomService/CheckService） |
| A06 | 全兼容更新 | 文件级还原 bundles/deps/patch；不跑 pnpm；提示重启一次 | 沙箱重置 bundles + patch.bak → check（强证据）→ restore → 断言 package.json/patch 还原、无 pnpm 调用 | 自动化 |
| A07 | 跨大版本不兼容 | 列出不兼容；whale 标 unverified；不静默改包 | fixtures manifest + evaluator | 自动化（helper fixtures） |
| A08 | 策略 A 命中兼容版本 | 选中版本正确、`--save-exact`、审计候选/拒绝原因 | **二期**（本版只保留决策表/接口，不实现安装） | 二期 |
| A09 | 无兼容版本 | 不安装不豁免；托盘黄；人工入口可用 | 二期（check 有 incompatible 时 phase=Blocked、托盘黄已在状态机实现） | 二期 UI |
| A10 | 离线升级失败 | 快速失败、无部分写入、可重试、原因正确 | 二期 | 二期 |
| A11 | 私有源/认证 | 只查私有源、不泄露、认证不落日志 | 二期 + Redactor 单测 | 二期 |
| A12 | 装到一半崩溃 | package.json/lock 恢复；run.json 处理正确；可续跑 | 沙箱模拟 journal 未完成 + 人工中断 restore，重启后 journal 检测 | 半自动 |
| A13 | 升级后回滚 | 恢复原 spec/version/lock；无 `file:` 残留 | 二期（本版 restore 支持文件级回滚，不含 pnpm） | 二期 |
| A14 | 恢复流程后还原 | agent-team + 第三方 + patch 正确恢复；顺序正确 | 沙箱模拟 recovery（bundles 重置为 base+web-app、patch 改 .bak）→ check → restore → 断言快照顺序 + agent-team 回归 | 自动化 + 破坏性演练 |
| A15 | 用户更新后手动改动 | 新装保留；主动删除不自动加回；patch 冲突给 diff | 沙箱多个场景（12.3/12.4） | 自动化 |
| A16 | 无快照/首次运行 | 不假装可还原；建基线并提示风险 | 空 data root + 沙箱 profile → status/check/restore 的失败语义 | 自动化 |
| A17 | App 运行中文件级还原 | 遵守锁、重试/等待、提示下次启动生效 | 沙箱伪造 profile\lock（活 PID）→ restore 等待/退避；释放后成功 | 自动化 |
| A18 | App 运行中包级升级 | 拒绝并提示完全退出；不 kill；退出后可继续 | 二期（本版无包级操作；状态机已保留 AwaitingExit） | 二期 |
| A19 | 自动重启竞态 | 识别新版本已启动；不抢装；进入 awaitingAppExit | 沙箱模拟版本变化 + App 进程（可用假进程名？）| 半自动 |
| A20 | guard 未运行期间更新 | 用最后快照；不先用坏状态覆盖；报告说明 | 沙箱：更新前快照 → 模拟新版本启动 → 首次 check/restore | 自动化 |
| A21 | 与插件管理器并发 | 等待/退避；无 torn snapshot；最终状态正确 | 沙箱并发改 package.json + snapshot 的稳定性测试 | 自动化（ProfileReader 双读） |
| A22 | client/patch 静态检查 | unverified/不可自动升级；报告具体缺失 | helper fixtures（缺 client 包、patch 文件缺失） | 自动化 |
| A23 | compatibility.json 异常/过期 | 不覆盖坏文件；旧豁免 inactive；不自动豁免新版本 | 沙箱 compatibility.json 损坏/旧版本 → check/restore | 自动化 |
| A24 | 中文/空格/自定义 DSH_HOME | 路径正确、UTF-8 无乱码、备份还原成功 | 沙箱路径 `loom 测试 目录\` | 自动化 |
| A25 | 单实例/开机自启 | 仅一个托盘；自启无闪窗/无重复；卸载自启生效 | 手工 + `install-autostart`/`uninstall-autostart` 检查注册表；`--tray` 二次启动 | 半自动 |
| A26 | DSH 卸载/换路径 | 进入"未找到 DSH"；不崩溃循环；可重新定位 | 沙箱指向不存在安装目录 → status/doctor；恢复后重新定位 | 自动化 |
| A27 | 残留 run.json | 按规则处理；不并行 pnpm；不误杀 | 沙箱伪造 run.json 死/活 PID | 自动化（LockManager） |
| A28 | 保留/磁盘满/敏感信息 | 按配额淘汰；保留冻结快照；日志无密钥；ACL 正确 | 单测保留策略；日志扫描 `_authToken/Bearer`；数据目录 ACL 手工检查 | 自动化 + 手工 |
| A29 | 通知/人工入口 | 同一事件只通知一次；点击可操作；不打断 | 状态机事件 id 去重（xunit）+ UI 手工 | 半自动 |
| A30 | 工具自身升级/迁移 | config/state 迁移；不丢快照/设置 | config/state schemaVersion 测试 + 旧文件备份 | 自动化 |
